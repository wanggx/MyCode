# 数据健康诊断与修复闭环

## 定位

个人量化平台没有平台方后台团队维护数据，所以必须把“手动补数”产品化。

目标不是做一个简单补录按钮，而是：

```text
平台发现数据缺口
  -> 给出影响范围
  -> 用户确认修复
  -> 修复后自动复检
  -> 留下修复记录
```

这个模块建议命名为：

```text
数据健康中心
```

或：

```text
数据诊断与修复
```

## 完整流程

```text
每日同步完成
  -> 自动质量扫描
  -> 发现数据问题
  -> 创建 data_quality_issue
  -> 评估影响范围
  -> 生成推荐修复方案
  -> 用户确认修复
  -> 创建 data_repair_job
  -> Worker 执行补录
  -> 重聚合周线/月线
  -> 自动复检
  -> 更新 issue 状态
  -> 生成修复报告
```

## 检查范围

第一版只做必要检查：

### 缺失类

- 某交易日完全没有数据。
- 某交易日股票数量低于预期。
- 某些股票缺日线。
- 日线存在但周线未聚合。
- 日线存在但月线未聚合。

### 异常类

- `open`、`high`、`low`、`close` 为空。
- `open`、`high`、`low`、`close` 为 0。
- `high < low`。
- `volume` 为空或异常为 0。
- `pre_close` 缺失。

### 一致性类

- 股票基础表存在股票，但日线表在交易日没有记录。
- 某日市场实际记录数明显低于最近均值。
- 日线数据更新到某日，但周线/月线没有覆盖该日期。

第一版不做复杂检查：

- 分钟级连续性。
- tick 连续性。
- 复权因子校验。
- 跨数据源一致性。
- 财务报表重述检查。

## 缺口对象

每个数据问题创建一个 issue。

示例：

```text
issue_code: DQ-20260604-001
market: A股
data_type: daily
date: 2026-06-04
expected_count: 5320
actual_count: 5298
missing_count: 22
severity: medium
status: open
```

详情记录保存缺失股票：

```text
trade_date: 20260604
ts_code: 000001.SZ
issue_type: missing_daily
message: 日线缺失
```

## 严重级别

建议规则：

```text
low:
  missing_count <= 5
  且不影响启用策略

medium:
  missing_count > 5
  或影响至少一个启用策略

high:
  整个市场某日缺失
  或影响今日信号生成
  或影响组合净值更新
```

## 影响范围评估

用户需要知道问题影响什么。

影响范围分四层：

```text
数据影响
  缺失 A股日线 22 只

因子影响
  MA20、MACD、KDJ、成交量斜率

策略影响
  放量突破、均线趋势、MACD/KDJ共振

结果影响
  今日信号可能漏选
  今日回测不建议采信
  模拟组合净值暂不更新
```

技术实现：

```text
DataImpactService
  affected_factors(issue)
  affected_strategies(issue)
  affected_signals(issue)
  affected_portfolios(issue)
```

第一版可以用静态映射：

```text
daily 缺失
  -> 影响所有基于日线的技术因子
  -> 影响所有启用的日频策略
```

## 修复方案

平台自动生成推荐修复方案。

### 方案 A：仅补缺失

默认推荐。

```text
市场：A股
数据类型：日线
日期：2026-06-04
标的：缺失的 22 只股票
补录方式：仅补缺失
后置动作：
  - 合并数据
  - 重聚合周线/月线
  - 自动复检
预计耗时：1-2 分钟
```

### 方案 B：覆盖重拉当日

用于数据整体异常。

```text
市场：A股
数据类型：日线
日期：2026-06-04
标的：全市场
补录方式：覆盖当日
后置动作：
  - 合并数据
  - 重聚合周线/月线
  - 自动复检
  - 可选重跑策略
预计耗时：5-8 分钟
```

### 方案 C：忽略并标记

用于源站确实没有数据，或用户确认不影响当前研究。

```text
状态：ignored
说明：用户手动忽略
```

## 用户确认选项

确认修复前展示：

```text
[x] 修复后自动复检
[x] 修复后重新聚合周线/月线
[ ] 修复后重新运行受影响策略
[ ] 修复后重新生成今日信号
```

默认勾选前两项。

策略重跑和信号重建可能耗时，默认不勾选。

## 执行步骤

创建修复任务：

```text
task_type = repair_missing_data
```

步骤：

```text
1. 创建修复任务
2. 加载缺失清单
3. 调用数据源补录
4. 写入临时表
5. 合并到正式表
6. 重聚合周线/月线
7. 自动复检
8. 生成修复报告
9. 可选重跑策略
```

每一步写入 `task_step`。

## 自动复检

修复完成后必须重新扫描同一范围。

示例：

```text
修复前：
expected_count: 5320
actual_count: 5298
missing_count: 22
complete_rate: 99.59%

修复后：
expected_count: 5320
actual_count: 5320
missing_count: 0
complete_rate: 100.00%
```

复检通过：

```text
issue.status = resolved
repair_job.status = success
```

复检失败：

```text
issue.status = open 或 failed
repair_job.status = failed
记录失败股票和失败原因
```

## 修复报告

每次修复保存报告快照。

内容：

```text
修复编号
关联 issue
修复方式
修复前快照
修复后快照
补录股票数
失败股票数
执行步骤
后置任务
用户选项
开始时间
结束时间
```

## 前端页面设计

建议放在“数据中心”。

### 数据健康总览

- 今日完整率
- 缺口问题数
- 异常问题数
- 受影响策略数
- 最近修复结果

### 缺口列表

字段：

```text
缺口编号
市场
数据类型
日期范围
缺失数量
严重级别
影响范围
状态
操作
```

操作：

```text
查看
修复
忽略
```

### 缺口详情

展示：

- 基础信息
- 缺失股票明细
- 影响范围
- 推荐修复方案
- 用户确认选项
- 历史修复记录

### 修复任务详情

展示：

- 当前状态
- 步骤进度
- 修复前后对比
- 失败原因
- 复检结果

## 第一版最小实现

优先实现：

```text
1. 扫描某日 A股/港股日线完整率
2. 生成缺失股票列表
3. 展示影响策略
4. 一键仅补缺失
5. 补完自动复检
6. 保存修复记录
```

不要第一版就做：

- 多数据源自动切换
- 复杂异常检测
- 复权校验
- 分钟数据修复
- 自动策略重跑链路
